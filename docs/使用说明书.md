# Plostain 使用说明书

> 版本：v0.1（2026-09-26）
> 适用对象：第一次使用 Plostain 的人（包括开发者本人）

Plostain 做一件事：你给它一份学习材料，它出一张小型诊断卷。你做完以后，它告诉你卡在哪一步、证据是哪几道题，以及下一卷应该测什么。

它不是题库，也不打分排名。每道题出之前，它都先想好“这道题要区分哪两种学生状态”“有某种误解的人会怎么答”，并把这些写进一张**设计卡**，在你作答前就**封存**。交卷后再打开封存区，对照它的押注有没有猜中。

---

## 一、第一次使用：安装与启动

### 1. 准备

- 电脑上装有 **Node.js 22.13 或更高版本**。
  在终端输入 `node -v` 查看版本。
- 项目文件夹：你把这个项目放在电脑上的那个文件夹（里面有 `package.json`）。

以下所有命令都要在这个文件夹里运行。

### 2. 安装依赖（只需要做一次）

```bash
npm run install:ci
```

### 3. 启动网站

有两种启动方式，按需要选一种：

| 命令 | 用什么出题 | 花钱吗 | 什么时候用 |
| --- | --- | --- | --- |
| `npm run dev:mock` | 固定的示例数据（mock） | 不花 | 想先看看界面、熟悉流程 |
| `npm run dev` | 真实模型（见第五节） | 花 token | 真正要出卷、做题 |

启动后，用浏览器打开 **http://localhost:5173** 。

- 终端窗口不能关，关掉网站就停了。
- 要停止网站，在终端里按 `Ctrl + C`。
- 同一时间只能开一个。想从 mock 切到真实模型，先 `Ctrl + C` 停掉，再运行另一个命令。

> mock 模式无论你贴什么材料，出的都是同一套“Python 浅拷贝”示例题。这是正常的，它只用来演示流程。

## 二、完整流程一览

```
① 粘贴材料 → ② 看材料地图 → ③ 生成练习（自动审核）→ ④ 作答 → ⑤ 看诊断与讲评 → ⑥ 按建议再出一卷
                                   ↓（教师模式）
                                 审题：删 / 改 / 单题重出 → 发布
```

左侧导航栏对应这些步骤：**学习材料 → 材料地图 → 练习卷 → 诊断与讲评**，下面还有**历史记录**和**模型与调用日志**。灰色的项表示还不能进入（比如还没交卷，就没有诊断）。

## 三、每一步怎么做

### ① 新建练习：粘贴材料

1. **材料标题**（选填）：不填的话，会取材料开头的几个字。
2. **来源**：笔记 / 教材 / 学习对话 / 错题 / 其他。
3. **粘贴材料**：课本的一节、你的笔记、和破卷的对话记录都可以。
   - 至少 80 字，最多 20,000 字。导入的文件超过 2 万字会自动按段落切开，你选导入第几段。
   - 超过上限会**直接拒绝**，不会偷偷截掉后半段。材料太长就拆成几段，分别出卷。
   - 保留原文和例子。材料越具体，出的题越有依据。
4. **本轮练习模式**（重要，见下表）。
5. **练习目标**：

   | 目标 | 题量 | 特点 |
   | --- | --- | --- |
   | 全面练习 | 6～10 题 | 覆盖主干知识点，各能力层级都有 |
   | 综合迁移 | 5～8 题 | 偏重“认出该用什么”、换情境的题 |
   | 快速诊断 | 3～5 题 | 优先哨兵题，最快找到问题 |
   | 完整练习 | 随材料，最多 25 题 | 长材料用：先出核心题，再自动补齐所有主干知识点，最后从易到难排列 |

   “全面练习”出完题后，如果还有主干知识点没有题测到，也会自动补题（总数最多 14 题）。

6. 点 **生成材料地图**。

**自测模式和教师模式的区别**

| | 自测模式 | 教师模式 |
| --- | --- | --- |
| 适合 | 自己出题自己做 | 给别人（比如家教学生）出题 |
| 审题页 | 没有，审核完直接进入作答 | 有，可以看答案、删改题目 |
| 答案和设计卡 | 交卷后才解锁 | 出题后就能看 |
| 地图的“易错处” | 交卷后才解锁 | 一直可见 |

自己出题又自己做，就选**自测模式**。否则你会先看到答案和易错点，等于被剧透，诊断就不准了。

> 模式在第①步选定后不能再改。想换模式，就重新新建一次。

### ② 材料地图

地图是出题用的“索引”，不是试卷。它包含：

- **知识点**：每个都附一句原文（引号里的部分），标明“主干”还是“次级”。
- **依赖**：哪个知识点以哪个为前提。
- **隐含前置**：材料默认你已经会、但没讲的东西。
- **边界**：材料“没讲透”的，和“紧邻但没涉及”的。出题会避开后者。
- **可验证性**：答案能不能靠运行代码、代入计算来验证。
- **易错处**：学生最可能想错的地方。自测模式下这一节是锁住的。
- **适合 / 不适合 / 为什么**：这份材料适合出什么样的卷。

你可以做的操作：

- 觉得地图没读懂材料，点 **重新生成地图**。
- 在右边改**练习目标**，然后点 **生成练习**。

生成练习分两步，页面上会显示进度和已用秒数：

1. **出题并封存设计卡**
2. **盲解 + 审核**：另一个模型在看不到答案的情况下先做一遍，审题模型对比后逐题检查。有问题的题修改一次再审一次，仍有问题就删掉。

> 用真实模型时，每一步可能要**一到几分钟**，请不要关闭页面。
> 如果中途关了页面，下次打开这张卷，会出现 **继续审核** 按钮，点它接着做。

### 覆盖情况（审题页、结果页都有）

程序用每个知识点的原文锚点，算出它在材料里的位置，再统计：
- **主干知识点覆盖了几个**，没测到的会列出名字；
- **材料前段 / 中段 / 后段各有多少题涉及**，用来发现“只从材料开头出题”的情况。

画地图时如果发现知识点全部来自材料前面，会自动重画一次；重画后仍然这样，地图页会显示黄色提示。

### 公式、程序验算、对照组（审题页、结果页）

- **公式**：题目里的数学式、物理量、化学式都用公式排版（KaTeX），网页和导出的 PDF 一致。化学式也支持，比如 $\ce{2H2 + O2 -> 2H2O}$。
- **程序验算**：每道能用程序验证的题，都带一段出题模型写的 Python 验算程序。系统在**隔离的沙箱**里真的运行它（碰不到你电脑上的文件），结果显示在题号旁边：
  - 绿色“验算通过”；红色“验算未通过”（会交给审核模型修改或删除）；黄色“验算程序出错”；灰色“无法程序验算”（纯概念题）或“未验算”（本机桥没开）。
  - 点开“设计卡”能看到验算程序和它的运行输出。
  - 老师改了答案，会自动重新验算。
- **对照组**：同一组的题旁边标着“对照 P1 · 看似相同、实则不同”。程序会检查：每组至少两道题、两题不能只差几个数字（伪变式）、“看似相同”的两题测的东西必须真的不同。发现的问题会交给审核模型，也会显示在审题页上。对照标记只给老师看，学生作答页和导出的试卷上没有。
- **程序检查**：单选题选项数要整卷一致、公式要写成公式（不能用 ³ 这类上标字符），不符合的会在审题页列出。

验算需要本机桥。用 `npm run dev` 启动时会自动带上；桥的代码更新后，要关掉网站重新运行一次 `npm run dev` 才会生效。

### ③ 审题（仅教师模式）

每道题下面有三个可以展开的部分：

- **设计卡**：诊断目的、难在哪、配对题、封存时间，以及**错答押注**（“有某种误解的学生会答什么”）。
- **来源与出题理由**：这道题来自哪个知识点、对应哪句原文、为什么这样出。
- **审核记录**：盲解的答案、审核发现的问题、审核结论（保留 / 修改 / 删除）、卷面评估。

每道题有三个按钮：

| 按钮 | 作用 |
| --- | --- |
| **编辑** | 修改题干、选项、答案、解析、诊断目的、错答押注。保存后会重新封存。**改了题面，记得把错答押注也一起改。** |
| **单题重出** | 可以写一句要求（例如“拆成两问”）。新题同样会经过盲解和审核。旧题保留在“已删除的题”里。 |
| **删除** | 这道题不再出现在卷面上，但记录会保留。 |

改完后点页面底部的 **发布给学生**，进入作答页。

> 改动之后，需要重新点一次“发布”。

### ④ 作答

- 页面只显示题干和选项，不会显示任何答案或提示。
- 题目**故意**不按知识点分组，也不写“本题考查……”。认出该用哪个知识，本身就是要练的。
- 每道题除了填答案，还要标**有多确定**：
  - **稳**：很确定
  - **犹豫**：不太确定
  - **蒙**：猜的

  信心是**必填**的。只点一下，但诊断很依赖它：“错且稳”往往说明有一个顽固的误解，是最值得讲的。
- **总用时**会自动计时。想填准确的分钟数，也可以自己改。
- 答案会自动存在浏览器里，刷新页面不会丢。
- 全部标完信心后，按钮会变成 **交卷**。交卷后开始批改和诊断，也需要等一会儿。

> 一张卷只能交一次。交卷后，所有题目和设计卡都变成只读。

### ⑤ 诊断与讲评

从上到下依次是：

1. **顶部数字**：答对几题、错且“稳”几题、对但“蒙”几题、错答押注命中率、用时。
2. **诊断**，分三层，不混在一起：
   - **① 观察到的事实**：哪题对、哪题错，信心是什么。只陈述，不解释。
   - **② 推测的学生状态**：每条都写明涉及的知识点或误解、**证据题号**、置信度（低 / 中 / 高）和理由，以及排除了哪些其他解释。
   - **③ 证据不足**：哪些结论现在还下不了，需要什么题来补。
   - **点任何题号小标签（如 `Q4`），页面会跳到那道题并闪一下。**
3. **封存区对照：错答押注**
   - **命中**：你的错答和出题时的押注一致。
   - **预测外的错答**：押注没猜到。说明出题时对学生的理解有盲区。
   - **押注了但没出现**：你没有那种误解，这是好事。
4. **讲评**：按“错且稳 → 错且犹豫 → 对但蒙”的顺序挑题，写出旧想法在哪一步失效、一个更简洁的正确画面，并用新画面把题走一遍。
5. **目前看来（学生状态快照）**：每个知识点目前看来是已掌握、不稳、未掌握，还是证据不足。
6. **逐题**：你的答案、标准答案、解析、批改方式（规则判 / 模型判），以及已解锁的设计卡和审核记录。
7. **下一轮建议**，以及 **按建议再出一卷** 按钮。
8. **给开发者的备注**（折叠）：哪道题的设计损失了信息、最没把握的判断是哪条。
9. **材料地图的易错处**（已解锁）。

**关于“推测”的两条规则**（由程序强制执行，不靠模型自觉）：

- 每条推测至少要有一道证据题，没有就会被移到“证据不足”。
- 只有一道题支持的推测，置信度最高只能是“中”；要两道以上互相印证才能到“高”。
  如果系统因此改动了模型的结论，会在“系统规则修正”里写明。

> 诊断里的状态都是“目前看来”的假设，不是给你贴标签。新的证据可以推翻它。

### ⑥ 按建议再出一卷

在结果页底部点 **按建议再出一卷**。上一轮的“下一轮建议”会作为额外要求交给出题模型，同一份材料会再出一张卷。历史记录里，这种卷会标为“追踪卷”。

## 四、历史记录与调用日志

- **历史记录**：列出所有练习卷，包括时间、材料、目标、模式、状态、成绩和押注命中率。点任意一行，会自动跳到那张卷该去的页面（审题 / 作答 / 结果）。
  数据存在本机数据库里（项目文件夹下的 `.wrangler/state`），关掉程序再打开也还在。**不要删除这个文件夹。**
- **模型与调用日志**：
  - 上半部分：6 个角色现在各用哪个模型，密钥有没有配置好。
  - 下半部分：每一次模型调用的时间、角色、模型、提示词版本、是否解析成功、token 数和耗时。解析失败的调用可以展开，看模型的原始输出。

## 五、换模型

Plostain 有 6 个“角色”，每个角色可以用不同的模型：

| 角色 | 做什么 | 对能力的要求 |
| --- | --- | --- |
| mapper | 读材料、画地图 | 中高 |
| generator | 出题、写设计卡 | **最高**（决定题目质量） |
| solver | 看不到答案，把题做一遍 | 中（最好和 generator 用不同模型） |
| reviewer | 审题、修题 | 高 |
| grader | 批改简述题、写法不同的短答题 | 中 |
| diagnostician | 诊断与讲评 | **最高** |

**换模型只需要改一个文件**：项目根目录的 `plostain.config.ts`。找到 `roles` 这一段，改对应角色的 `provider` 和 `model`，保存后重启网站即可。

可选的 provider：

| provider | 说明 | 需要什么 |
| --- | --- | --- |
| `glm` | 智谱 GLM（现在的默认） | `.env` 里的 `LLM_ENDPOINT`、`LLM_API_KEY` |
| `fable` / `opus` | Anthropic API（两套配置） | `.env` 里的 `FABLE_*` / `OPUS_*` 三行：地址（留空=官方）、密钥、模型 |
| `claude_cli` | 本机 `claude -p`，走个人订阅 | 另开一个终端运行 `npm run claude-bridge` |
| `mock` | 固定示例数据 | 什么都不用 |

例子：把出题和诊断换成 Claude Fable（走 API）：

```ts
generator: { provider: "fable", model: "claude-fable-5-1", effort: "high" },
diagnostician: { provider: "opus", model: "claude-opus-5-5", effort: "high" },
```

例子：走个人订阅：

```ts
generator: { provider: "claude_cli", model: "fable" },
```

**注意：**

- 密钥**只**放在 `.env` 文件里，不要写进 `plostain.config.ts`，也不要发给别人。`.env` 不会被提交到仓库。可以参考 `.env.example` 的格式。
- `claude_cli`（订阅额度）**只限你本人在本机使用**。给别人用，必须改走 API（`fable` / `opus`）。
- **当前分配**：盲解（solver）用 **GLM**，其余 5 个角色走**本机订阅的 Opus 5.5**（不额外花钱）。盲解和出题用不同模型，更容易发现题目本身的问题。中转 API 的 Fable / Opus 留在配置里备用。
- **订阅里的 Fable 5.1 要另买用量**（实测会提示 “requires usage credits”），所以没用它。
- `npm run dev` 会自动在后台启动本机 claude 桥；如果你已经在别的终端开着它，就不会重复启动。前提是电脑上的 claude 已经登录过订阅账号。

## 六、常见问题

**Q：点了按钮，一直在转圈？**
用真实模型时，出题、审核、诊断每一步都可能要几分钟，这是正常的。转圈旁边的秒数在走，就说明还在运行。想确认，可以去“模型与调用日志”看有没有新的记录。

**Q：显示“出错了”，下面有“模型原始输出”？**
说明模型的回答两次都没通过格式检查。可以展开看它到底输出了什么，然后点“重试”。如果某个模型经常这样，考虑给那个角色换一个模型。

**Q：显示“缺少环境变量……”？**
`.env` 里没配对应的密钥。检查 `.env` 文件，或者在“模型与调用日志”页面看哪个角色的密钥显示“缺少”。

**Q：交卷后显示“诊断没有完成”？**
你的答案已经保存了，只是诊断那一步出错（通常是网络或模型问题）。点 **重新诊断** 即可，不需要重新作答。

**Q：审核后提示“材料可能撑不起这张卷”？**
审核删掉了太多题，剩下的题数低于下限（快速诊断是 3 题，其他是 4 题）。系统不会凑数。可以换一份更完整的材料，或者选题量少的“快速诊断”。

**Q：想改一张已经交过的卷里的题？**
不行。交卷后题目和设计卡都封存了，这是为了保证“押注在作答之前”。可以用同一份材料再出一张新卷。

**Q：自测模式下想先看看答案？**
交卷前服务器根本不会把答案发给浏览器，所以看不到。想先审题，就用教师模式出卷。

**Q：怎么确认程序本身没坏？**
运行下面的命令。它会用 mock 数据自动跑一遍完整流程，全部通过会显示 `pass 6`、`fail 0`。

```bash
npm test
```

## 七、名词对照

| 名词 | 意思 |
| --- | --- |
| 材料地图 | 从材料里整理出的知识点、依赖、易错处、边界。它是出题的索引，不是试卷 |
| 设计卡 | 每道题的“幕后说明”：诊断目的、难在哪、错答押注、配对题 |
| 错答押注（错答地图） | 出题时预测“有某种误解的学生会答什么”。交卷后用来验证 |
| 封存 | 设计卡在作答前写好并打上时间戳，之后不能修改 |
| 盲解 | 另一个模型在看不到答案的情况下把题做一遍，用来发现题目本身的问题 |
| 哨兵题 | 短而快的题，专门检验一个关键能力。它错了，后面依赖它的题的错误就要重新解释 |
| 配对题 | 两道题合起来读才能区分不同的误解，比如“长得像但原理不同” |
| 错且稳 | 答错了但标了“稳”，往往是顽固的误解，最值得讲 |
| 对但蒙 | 答对了但标了“蒙”，不算真正掌握 |
| 命中率 | 你的错答中，有多少被出题时的押注猜中 |
